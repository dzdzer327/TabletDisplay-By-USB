# Android 视频流协议（开发期 v1）

Android 客户端只在设备回环地址 `127.0.0.1:27183` 监听 TCP。开发期由 ADB 建立电脑到平板的端口转发：

```powershell
adb forward tcp:27183 tcp:27183
```

Windows 发送端连接电脑本机 `127.0.0.1:27183`，连接会由 ADB 转发至平板。该设计不会让 Android 应用监听 Wi-Fi 或公共网络接口。

TCP 流由一系列“大端序固定头部 + H.264 访问单元”组成。每个头部 32 字节：

| 偏移 | 类型 | 含义 |
|---:|---|---|
| 0 | `uint32` | Magic：`0x54445350`（`TDSP`） |
| 4 | `uint32` | 协议版本：`1` |
| 8 | `uint32` | 编码宽度 |
| 12 | `uint32` | 编码高度 |
| 16 | `uint32` | 标志位 |
| 20 | `uint32` | 紧随其后的负载字节数，最大 8 MiB |
| 24 | `uint64` | 显示时间戳，微秒 |

标志位：

- `0x1`：负载为 H.264 SPS/PPS 等解码配置，对应 `BUFFER_FLAG_CODEC_CONFIG`。
- `0x2`：负载包含 IDR/关键帧。
- `0x4`：流结束。
- `0x8`：早期独立鼠标叠加实验包；当前 Android 仅为兼容旧控制器而忽略，Windows 新版不再发送。

H.264 负载按一个完整访问单元一包发送，使用 Annex B 起始码。连接建立或编码参数变化后，Windows 必须先发送 SPS/PPS 配置，再发送 IDR 帧。Android 根据包内宽高创建或重建 `MediaCodec`，解码结果直接输出到全屏 `SurfaceView`。

当前测试设备的 DXGI/IDD 画面已经包含 Windows 系统鼠标。Android 不再额外绘制箭头，避免原鼠标与映射鼠标同时出现。

## 触控回传协议（开发期 v1）

Windows 只在电脑回环地址 `127.0.0.1:27184` 监听触控连接。Android 连接设备本机的同一端口，开发期由 ADB 建立平板到电脑的反向端口映射：

```powershell
adb reverse tcp:27184 tcp:27184
```

每个触控帧由 16 字节大端序头部和 1～10 个触点记录组成：

| 偏移 | 类型 | 含义 |
|---:|---|---|
| 0 | `uint32` | Magic：`0x54444950`（`TDIP`） |
| 4 | `uint32` | 协议版本：`1` |
| 8 | `uint32` | 本帧触点数量 |
| 12 | `uint32` | 保留，当前为 0 |

每个触点紧随头部，占 20 字节：

| 偏移 | 类型 | 含义 |
|---:|---|---|
| 0 | `uint32` | 指针 ID，范围 1～256 |
| 4 | `uint32` | 动作：1 按下、2 移动、3 抬起、4 取消 |
| 8 | `uint32` | 横向归一化坐标，范围 0～1,000,000 |
| 12 | `uint32` | 纵向归一化坐标，范围 0～1,000,000 |
| 16 | `uint32` | 压力，范围 1～1024 |

Android 每次 `MotionEvent` 都发送当时仍参与手势的全部触点。Windows 根据虚拟显示器的桌面矩形恢复绝对坐标，并使用 `InjectTouchInput` 注入原生 Windows Touch 事件。连接意外中断时，Windows 会主动取消仍处于按下状态的触点，避免出现“手指卡住”。
