# 阶段一：IDD 虚拟显示器验证

## 本阶段目标

在专用测试机上，以 Microsoft IddSample 验证 IddCx 驱动生命周期和桌面帧交换链；成功后才开始将其替换为 Tablet Display 的动态连接逻辑。

## 前置条件

- Windows 11 测试机，建议为虚拟机或非主力机器。
- Visual Studio 2022、Windows SDK 与 Windows Driver Kit 已安装。
- 具备管理员权限。
- 不接入 Android 平板；本步骤不传输视频。

## 验收步骤

1. 运行 `windows/driver/Get-IddSample.ps1` 并确认取得 `IddSampleDriver.sln`。
2. 在 Visual Studio 中，以 `Debug|x64` 构建 `IddSampleDriver` 和随附部署应用。
3. 只在测试机上按上游 README 的步骤启用测试签名、安装驱动并启动部署应用。
4. 打开 Windows“设置 → 系统 → 显示”，确认出现由样例创建的虚拟显示器。
5. 选择“扩展这些显示器”，把一个普通窗口拖入该屏幕；确认显示设置不会崩溃或循环重连。
6. 保留以下记录：Windows 版本、GPU 型号和驱动、WDK 版本、构建配置、显示设置截图、事件查看器错误。
7. 卸载样例驱动、关闭测试签名并重启，确认虚拟显示器消失。

## 通过标准

- 驱动安装后 Windows 能枚举至少一个额外显示器。
- 额外显示器可参与“扩展”拓扑，且无需重启桌面会话。
- 把窗口移至该显示器不会导致 `dwm.exe`、驱动宿主或显示设置崩溃。
- 卸载或停止样例后，额外显示器不再保留。

## 已知且预期的限制

上游样例会在设备启动时立即创建固定数量的显示器，并且不会编码或发送帧。这在本阶段是预期行为，不能作为产品方案。

## 下一项实现工作

验证通过后，创建 `TabletDisplayDriver`：

1. 仅声明一台显示器和本项目的模式集合：720p、1080p、1920×1200、2560×1600，均为 60 Hz。
2. 将“显示器到达/离开”改由用户态连接服务的会话状态控制，而非设备 D0 启动即创建。
3. 在交换链线程中先加入无损帧计数、时间戳和 GPU 复制；尚不引入编码器。
4. 规定失去交换链时必须停止处理线程并释放所有 DXGI 资源。

## 风险处置

- 若 Windows 无法加载驱动：先检查证书、测试签名状态和 WDK/SDK 版本是否匹配。
- 若设备管理器正常但显示设置没有显示器：检查部署应用是否运行及 IddCx 诊断日志。
- 若显示设置或桌面窗口管理器不稳定：停止测试，卸载驱动后再分析转储；不要在主力系统继续调试。
