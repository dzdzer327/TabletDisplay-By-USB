## 真机补测发现的问题

1. **设置应用后首次点按丢失，已复现。** 重新启用触控并切换帧率后，第一下点按没有增加测试窗口计数；随后点按成功。Android `TouchInputSender` 只发送、不读取连接关闭通知，空闲时不会及时发现服务重建，需发送后触发错误再重连。应修复输入连接恢复机制并回归首个手势，不应把本项写成通过。
2. **横向视频源在竖向平板上拉伸，截图可见。** 本次 Windows 输出 1920×1200，Android 屏幕截图 1600×2560，画面填满屏幕但比例失真。应补充等比适配或明确的方向匹配策略；本观察不代表已测试 Windows 原生竖屏模式。
3. **持续 120fps 未达到验收证据。** 模式和编码目标均可设为 120，但本图案仅观测到约 63～64fps 编码，未测得 Android 实际解码/呈现 120fps。另一次系统显示状态采样报告平板支持 60/120Hz、当时实际为 60Hz；采样在 30fps 阶段，不能据此反推整个 120fps 阶段的物理刷新率。需独立区分源更新、编码、解码和呈现瓶颈。
4. **文件被占用时卸载无法完整恢复。** 测试脚本最初从安装目录加载设置模型程序集，使 EXE 在脚本进程存活期间被锁定。卸载已移除新增驱动、快捷方式及安装标记，但删除 EXE 失败，留下该 EXE 和卸载注册，且原卸载器/标记已删除，无法直接再运行原卸载入口。占用由测试方法引入，不能据此宣称正常退出后的卸载必然失败；但失败后的恢复能力确实不足。本次未修改安装器代码。测试脚本已改为从隔离副本加载程序集，避免下次制造同类占用。

4. 建议先标为 GitHub Pre-release，并明确上述未验收项。只上传选定版本产物与匹配校验文件，不上传整个 dist、私钥、调试日志或开发环境。
