# USB 有线扩展屏幕软件需求分析

## 1. 项目目标

开发一套软件，使 Android 平板通过 USB 数据线成为 Windows 10/11 电脑的第二块“扩展显示器”。

用户连接数据线并启动软件后，Windows 应识别出一个额外显示器；用户可在系统“显示设置”中调整其位置、分辨率、缩放、横竖屏与主副屏关系。平板显示该虚拟屏幕的内容，并可将触控操作回传给电脑。

本项目不依赖平板的视频输入能力；USB 仅承担画面与控制数据传输。

## 2. 目标用户与使用场景

目标用户为拥有 Windows 电脑、Android 平板和 USB 数据线的个人用户。

典型流程：

1. 用户在电脑与平板分别安装客户端。
2. 用户用 USB 数据线连接两端。
3. 用户允许平板端所需权限，并启用指定的数据连接方式。
4. Windows 自动出现名为“Tablet Display”的额外显示器。
5. 用户在 Windows 设置中选择“扩展这些显示器”。
6. 用户将窗口拖到平板，或在平板上用触控操作电脑应用。

## 3. 功能需求

### 3.1 Windows 虚拟显示器

- 软件安装后应提供一个 Windows 间接显示驱动（Indirect Display Driver）。
- 平板连接时，驱动应向 Windows 报告一台虚拟显示器；断开时应移除该显示器。
- 首期支持以下显示模式：
  - 1280×720，60Hz
  - 1920×1080，60Hz
  - 1920×1200，60Hz
  - 2560×1600，60Hz（设备性能允许时）
- 支持横屏与竖屏。
- 支持 Windows 原生多显示器设置，包括显示器排列、缩放、设为主屏、复制或扩展。
- 平板未连接时，默认不保留幽灵屏幕。

### 3.2 有线连接与会话管理

- 首期使用 USB 数据通道建立电脑与平板之间的点对点连接。
- 开发版可使用 ADB 端口转发；正式版本应优先支持 USB 网络共享或自定义 USB Accessory 通道，避免要求普通用户打开 USB 调试。
- 平板连接、断开、休眠、旋转、应用切换后，应能自动恢复或提示重连。
- 同一电脑首期只支持连接一台平板。

### 3.3 画面传输

- Windows 端从虚拟显示器的交换链获取画面。
- 画面应使用硬件 H.264 编码；设备支持时可选 H.265。
- Android 端使用 `MediaCodec` 硬件解码，并以全屏、低延迟方式渲染。
- 默认目标为 60fps；性能不足时自动降至 30fps 或降低码率/分辨率。
- 支持传输独立鼠标光标，减少画面端到端延迟。

### 3.4 输入回传

- 支持平板单指触控映射为 Windows 鼠标移动、单击、拖拽与滚轮操作。
- 支持双指滚动、缩放等基础手势。
- 可选支持多点触控，以 Windows Touch 事件方式注入。
- 支持平板软键盘输入，并将文本或按键发送至 Windows。
- 输入映射必须随平板方向、分辨率、Windows 缩放比例正确变化。
- 应提供“仅显示，不接收触控”的开关。

### 3.5 设置与诊断

- Windows 端提供状态页：连接状态、分辨率、帧率、编码器、码率、延迟、丢帧数。
- Android 端提供连接状态、当前分辨率、帧率、触控开关与旋转锁定。
- 支持用户手动选择分辨率、帧率上限、画质优先或低延迟优先。
- 连接失败时应给出可读提示，例如“数据线仅充电”“未授权 USB 网络”“驱动未正常加载”。

## 4. 非功能需求

| 项目 | 首期目标 |
|---|---|
| 端到端画面延迟 | 1080p60 下低于 80ms；理想目标低于 40ms |
| 帧率 | 默认 60fps，性能不足时稳定运行在 30fps |
| CPU 占用 | 优先使用 GPU 编解码，避免持续高 CPU 占用 |
| 稳定性 | 连续运行 8 小时不崩溃、不明显内存增长 |
| 兼容性 | Windows 10 22H2、Windows 11；Android 10 及以上 |
| 安全性 | 仅允许已配对的 USB 设备建立会话；不监听公共网络端口 |
| 可恢复性 | 平板断连后 10 秒内可自动恢复，或一键重新连接 |

## 5. 系统架构

系统由四个部分组成：

1. **Windows 间接显示驱动**  
   创建并管理虚拟显示器，向 Windows 提供显示模式，并接收系统为该显示器生成的桌面帧。

2. **Windows 用户态服务/桌面客户端**  
   负责设备发现、会话协商、硬件视频编码、数据传输、输入事件注入、日志与设置界面。

3. **USB 传输层**  
   将视频、控制命令和输入事件在电脑与平板之间传输。视频优先低延迟，控制和输入优先可靠送达。

4. **Android 平板客户端**  
   负责 USB 连接、视频硬解码与显示、触控采集、软键盘、状态展示和异常重连。

数据流：

`Windows 虚拟显示器 → GPU 编码 → USB 传输 → Android 硬解码与显示`

`Android 触控/键盘 → USB 传输 → Windows 输入注入`

## 6. 关键技术约束与风险

- 真正的扩展屏必须使用 Windows 虚拟显示驱动，普通屏幕截图软件只能实现镜像，不能让 Windows 出现可拖动窗口的第二屏。
- Windows 驱动的安装、签名和兼容性是发布阶段的高风险项；开发阶段可测试签名，正式发布需满足 Windows 驱动分发要求。
- 不同 Android 厂商对 USB 网络共享、后台运行、屏幕旋转和省电策略的限制不同。
- DRM/受保护视频内容可能无法被捕获或传输，这是操作系统与内容保护机制的限制。
- ADB 方案适合开发验证，但不适合作为正式产品的默认连接方式。
- 高分辨率、高刷新率依赖电脑 GPU 编码器、USB 带宽和平板硬解能力，应支持自动降级。

## 7. 首期范围与不做事项

首期必须实现：

- Windows 虚拟扩展显示器；
- Windows 与 Android 的 USB 连接；
- 1080p、60fps 目标画面传输；
- 单点触控、鼠标和基础键盘输入；
- 自动连接、断开检测和基础诊断。

首期不做：

- iPad、macOS、Linux 支持；
- 无线连接；
- 多平板同时扩展；
- 音频传输；
- Apple Pencil/压感绘图；
- HDR、DRM 内容播放；
- 跨网络远程访问。

## 8. 验收标准

项目首期完成时，应满足以下验收场景：

1. 在一台干净的 Windows 11 电脑和 Android 10+ 平板上安装后，可通过 USB 建立连接。
2. 连接成功后，Windows“显示设置”中出现第二台显示器。
3. 用户可将窗口拖动到平板，并能调整该屏幕的排列、分辨率和横竖方向。
4. 1080p60 的常规桌面操作画面流畅，无持续黑屏、花屏或明显卡顿。
5. 平板单击、拖拽、滚动和键盘输入可正确作用于 Windows 副屏。
6. 拔出数据线后，系统在合理时间内退出会话；重新连接后可恢复。
7. 连续使用 8 小时无应用崩溃、驱动崩溃或无法恢复的断连。

## 9. 建议实施阶段

- **阶段一：技术验证**  
  以 ADB 传输实现“虚拟显示器 → 平板显示”，暂不做触控与自动化连接。

- **阶段二：可用原型**  
  加入硬件编码、低延迟传输、鼠标/键盘回传和 Windows 设置页。

- **阶段三：产品化连接**  
  替换 ADB 为面向普通用户的 USB 连接方式，加入设备配对、自动重连、日志和兼容性处理。

- **阶段四：发布准备**  
  完成驱动签名、安装卸载、异常恢复、性能测试和多设备兼容性测试。
